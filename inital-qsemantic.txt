# قرآن

QURANIC VERSE SEARCH
Full Prompt · Architecture · Design System · Claude Code Handoff
Compiled from conversation — Yoonis × Claude  ·  March 2026

1. What We Built
A real-time Quranic verse identifier. You type a transliteration of a verse as you remember it — approximate, partial, phonetically off — and the system identifies the exact verse, shows the Arabic text, clean transliteration, and English translation, with a live confidence score.
The core insight: Claude's training knowledge of the Quran is encyclopedic. Instead of a static dataset + fuzzy string matching, we use the model itself as the lookup engine — passing the user's phonetic attempt as a prompt and receiving structured JSON back with the verse reference, Arabic, and confidence.

2. Prior Art — GitHub Research
Before building, we surveyed existing open-source Quran search projects. Here's what exists and why we took a different approach:
EXISTING PROJECTS
Project
Assessment
alfanous
Python library. Boolean search, root/lemma, wildcards, fielded search. pip install alfanous3. Best for static text search. No transliteration matching.
quran-search-engine
TypeScript library. Exact + lemma + root + fuzzy matching. UI-agnostic. Good for React/Vue. Requires pre-loaded dataset. No transliteration input.
quranic-search-v2
React + Django + Flask. Word2Vec semantic search. Complex to self-host. Conceptually interesting but heavyweight.
QuranHub API
FastAPI + PostgreSQL. 430+ editions, morphological analysis, audio. REST API. Non-commercial license. No transliteration search.
quranic (0arm)
Sentence embeddings, semantic search. Python only. Minimal docs. Interesting but requires GPU/model download.
pure-quran-search
English concordance only. CLI. Very simple. Not Arabic/transliteration.
None of these solve the specific problem: someone hears or remembers a verse phonetically and wants to identify it from a partial, approximate romanization. This is the gap.

3. The Master Prompt
This is the exact system prompt used in the Claude API call. Copy this verbatim into your Claude Code implementation:
SYSTEM PROMPT — /V1/MESSAGES
You are a Quran verse identification system. The user types a transliteration (romanized Arabic) of a Quranic verse as they remember it — it may be approximate or partially typed. Identify the most likely verse match.

Respond ONLY with a JSON object, no markdown, no extra text:
{
  "found": true/false,
  "surah_number": 4,
  "ayah_number": 113,
  "surah_name": "An-Nisa",
  "surah_name_arabic": "النساء",
  "arabic": "full arabic text of the verse",
  "transliteration": "clean standard transliteration",
  "translation": "English translation",
  "confidence": 87,
  "match_notes": "very short note on what matched e.g. 'anzallahu + kitaaba matched distinctively'"
}

If confidence < 40 or no match, return: {"found": false}

Be generous — users type from memory, so partial/approximate matches count. Even 5-6 words typed is enough to identify a verse with high confidence if distinctive.
USER MESSAGE TEMPLATE
Identify this Quran verse transliteration (may be partial/approximate): "${query}"

4. UX Behaviour — The 'Withering Down' Effect
The user described the desired UX as the verse 'withering down as I continue typing' — meaning the system progressively locks in as more context is provided. Here's how that's implemented:
STATE MACHINE
State
Behaviour
idle
Input < 8 chars. No API call. Status dot: dim grey.
thinking
Debounce fired, API call in flight. Dot pulses gold. Skeleton shimmer shown.
found
Parsed JSON with found: true. Dot turns green. Result card slides in.
not-found
found: false or confidence < 40. Dot turns red. Message: 'keep typing'.
KEY UX DECISIONS
    • — not too eager, not too slow. Fires after user pauses, not on every keystroke. 900ms debounce
    • — every new keystroke cancels the previous in-flight request. No race conditions. AbortController
    • — fills from 0→N% as the result arrives. Visual feedback of match quality. Confidence bar
    • — e.g. 'anzallahu + kitaaba matched distinctively'. Builds user trust in the result. Match notes field
    • — shown during API call. Prevents layout shift when result arrives. Skeleton shimmer
    • — result card animates in. Feels like it's being 'resolved'. Slide-in animation
    • — prevents firing on single words that would return low-confidence results. Min 8 chars

6. Full React Component
Save this as src/App.jsx (or QuranSearch.jsx). It is a single-file self-contained component — no external dependencies beyond React itself.
FILE: SRC/APP.JSX OR QURANSEARCH.JSX
The component uses:
    • useState, useEffect, useRef, useCallback — from React
    • fetch() — native browser API, no axios needed
    • No external UI libraries — pure CSS-in-JS via the STYLE constant
    • API key — read from import.meta.env.VITE_ANTHROPIC_API_KEY
KEY FUNCTIONS
Function
Purpose
parseResult(text)
Strips markdown fences, JSON.parse, fallback regex extraction of surah:ayah reference.
search(query)
Async. Aborts previous request. Sets state. Calls /v1/messages. Parses response.
useEffect → debounce
Watches query. Clears timeout on each keystroke. Fires search() after 900ms pause.
The full source code is in the companion file: quran-search.jsx
